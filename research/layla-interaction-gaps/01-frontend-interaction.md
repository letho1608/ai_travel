## 3. Top 10 missing interactions for a layla-like feel

Ranked by likely impact on "does this feel like talking to an AI travel agent":

1. **Real conversational multi-turn chat.** The workspace assistant currently returns the same canned i18n line after every refine (PlanView.tsx:26, 122). A layla-like planner needs the assistant to (a) reply in actual sentences about what it changed and why, and (b) ask one clarifying question per turn (dates? budget? food pref?). **Requires backend reply text + a chat that renders it.**
2. **Streaming of assistant replies in the workspace.** Generation already streams SSE statuses (Planner.tsx:122); the refine path should stream the assistant's reply and/or incremental plan updates instead of a blocking POST (PlanView.tsx:102) with a bare `busy` line.
3. **An actually-rendered typing indicator.** The animation CSS is already there (globals.css:22) — wire it up during `busy` instead of/in addition to the text status (PlanView.tsx:118). Trivial win.
4. **Trip-parameter inputs or an interactive Q&A.** Nothing lets a user set dates, duration, budget, or start point (Planner.tsx:65-72, 105, 108); the duration translations exist but are dead (LocaleProvider.tsx:75, tests:255). A layla user expects "3 days in Hanoi, ~$200, 2 people" to be expressible explicitly.
5. **Chat-message editing / undo / "start over" in the chat panel.** Append-only conversation (PlanView.tsx:76) with recovery buried in a header button (PlanView.tsx:104). Users need to correct the last message without leaving the chat.
6. **Auto-scroll + persistent sticky input + "new plan" reset.** Messages cut off with no scroll management (globals.css:22), input is disabled while working (PlanView.tsx:122), and there is no chat-level reset — the three combine to make long sessions feel broken.
7. **Live plan state + last-updated + stale indicator.** One-shot fetch only (PlanView.tsx:96), no polling/SSE after load, no timestamp (G16/G17). A shared plan edited by a companion should surface "updated X min ago".
8. **Skeletons, optimistic updates, and retry on every failure.** No loading shells (G12), no optimistic slot swap (G13), and no retry actions in the workspace (G11). This is the fastest-visible polish win across all screens.
9. **Toast notifications.** Success/failure currently both render as the same top-of-page status line (PlanView.tsx:118); layered toasts (success green, error red, auto-dismiss) would make mutation feedback land where the user is looking.
10. **Accessible overlays + keyboard parity.** Drawers need `role="dialog"`/focus trap/Escape (G25), a skip link (G28), an error boundary (G26), and keyboard-accessible map markers (G27) before a layla-class experience can claim parity on desktop and AT.

## 4. Executive summary

The frontend is a disciplined, resilient form-driven app, not yet a conversational product. Its strengths are structural: universal disable-during-flight with ref-guards, SSE status streaming during the initial plan generation, thorough timeouts and 401 self-healing, a 19-locale i18n contract enforced by tests, solid clipboard/share feedback, and a genuinely good landing-page onboarding flow. The interaction gaps are concentrated in exactly the layer layla.ai sells: the conversation. The workspace "chat" is a single-line prompt whose replies are canned i18n keys (PlanView.tsx:26, 122) — there is no streaming reply, no rendered typing indicator (dead CSS at globals.css:22), no follow-up questions, no message editing or undo, and no auto-scroll. Trip parameters beyond a free-text sentence and a people count are absent (duration/budget/location are hardcoded or regex-inferred, Planner.tsx:65-72, 105, 108). After generation, there is no real-time feel: no polling, no last-updated timestamp, no stale indicator. Error handling is consistent but mostly dead-end (no retry buttons in the workspace; history has none), there are no skeletons or optimistic updates, and the offline story is half-built (data saved to `localStorage["offline-plan:…"]` but never read back). Accessibility is respectable at the surface (aria-labels, `aria-live`, reduced-motion) but missing focus traps, Escape handling, a skip link, an error boundary, and keyboard-accessible maps. To feel like layla.ai, the work is: make the chat a real streamed, multi-turn, editable conversation; add explicit trip-parameter inputs; add live plan state + timestamps; and unify loading/retry/toast/overlay patterns.
